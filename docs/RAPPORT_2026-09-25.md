## 2. Audit du 18/09 — lot L2 et ce qui l'accompagnait

### Le défaut, en une phrase

`actions/checkout` écrit le jeton GitHub dans la configuration git du runner **pour tout le reste
du run** : n'importe quelle étape suivante, action tierce comprise, pouvait le lire. Et les
scripts d'installation des paquets tournaient avec les droits du runner, qui porte les secrets.

### Ce qui a été posé

| Dépôt | PR | Contenu |
|---|---|---|
| FinanceAI | #989 | **L1** (`sanitizeContext` perdait la clé `__proto__` d'un `JSON.parse`), **L5b** (19 BLOCKER SonarCloud éteints par une ligne de config), **L2** (6 `checkout`, `--ignore-scripts`, 3 actions tierces épinglées au SHA) |
| Hubperso | #61 | L2 — 5 `checkout`, 3 `npm ci` |
| DriveAI | #379 | L2 — 6 `checkout`, `clasp` épinglé à 3.4.1 |
| JobAI | #20 | L2 — 3 `checkout` |
| CarAI | #127 | L2 — 3 `checkout`, dont `auto-merge.yml` |
| MemoryAI | #37 | L2 — 2 `checkout` |
| BatchChef | #101 | L2 — 2 `checkout` |
| hub-contract | #13 | L2 — et un **test neuf** qui reprend la garantie que `--ignore-scripts` supprimait |

### Trois choses qu'il fallait mesurer, pas supposer

- **`--ignore-scripts` ne casse pas les dépendances git.** Cinq dépôts dépendent de
  `github:MoKarade/hub-contract#v1.3.0`, dont le `dist/` n'existe que par son script `prepare`.
  Mesuré cache npm vide, puis sur un vrai runner : npm construit une dépendance git au moment de
  la **récupérer**, pas au moment d'exécuter les scripts. [Certain — mesuré deux fois]
- **Chez hub-contract, le piège de l'audit était réel.** Son `npm ci` déclenchait `prepare`, et
  c'était **le seul contrôle** du chemin d'installation des six consommateurs. La garantie est
  désormais découpée en deux : l'étape `Build` prouve la commande, `tests/cheminConsommateur.test.ts`
  prouve que `package.json` la déclare toujours. Sans la seconde, retirer `prepare` aurait cassé
  les six apps sans rien faire rougir.
- **Deux des trois comptes de l'audit valaient zéro chez FinanceAI** (`S6505 × 7`, `S8543 × 7`).
  C'est précisément pourquoi l'audit disait de re-mesurer.

## 3. Les alertes SonarCloud de DriveAI

Tu as collé la liste sans consigne. J'en ai tiré :

- **Un vrai défaut, dans trois dépôts.** `npx` est une commande d'**installation** : quand le
  binaire n'est pas local, il télécharge depuis le registre **et exécute les scripts
  d'installation** — exactement ce que `--ignore-scripts` venait de fermer. Mon recensement du
  lot L2 était ancré sur `npm ci` et ne voyait pas `npx`. **9 sites corrigés** en
  `npx --no-install` : DriveAI 1, FinanceAI 3, JobAI 5.
- **Un faux positif démontré** : le « secret Bearer » signalé en BLOQUANT dans
  `api/mcp/index.ts:207` est l'en-tête de défi de la RFC 9728, `Bearer resource_metadata="…"`.
  Aucun motif de secret réel dans le fichier. **C'est à toi de le marquer** dans SonarCloud (§8).

⚠️ **Une erreur de raisonnement de ma part, reconnue sur la PR** : j'avais d'abord affirmé que le
rouge SonarCloud de DriveAI #379 « n'était pas de cette PR ». C'était faux — les alertes étaient
dans les fichiers que la PR modifiait, et la porte est passée au vert sur un commit qui ne
changeait que deux lignes de workflow. Correction écrite en commentaire sur #379.

### Ce qui bloquait vraiment

| Dépôt | État avant | PR |
|---|---|---|
| **FinanceAI** | 🔴 **Pas installable du tout** : une seule icône, en SVG. Chrome exige une icône raster ≥ 192 px pour fabriquer l'app, et ne dit rien quand elle manque. | #991 |

| BatchChef | Les deux icônes servaient aussi de « maskable » : la marmite se faisait rogner par le masque rond d'Android | #102 |

### Ce qui a été ajouté partout

- `id` fixe : sans lui, changer un jour la page d'accueil de l'app installerait une **seconde**
  app au lieu de mettre à jour la première.
- `launch_handler: navigate-existing` : un lien depuis le hub réutilise la fenêtre ouverte.
  (`focus-existing` écarté : il ramène la fenêtre sans naviguer, donc ignore le lien.)
- Une garde par dépôt qui **relit les dimensions dans le fichier PNG** plutôt que de croire le
  champ `sizes` du manifeste. Un manifeste peut annoncer 512 px en servant un fichier de 192, et
  Chrome croit le fichier.

### Vérifié en production

Les **sept manifestes servis** ont été lus dans la réponse HTTP réelle après déploiement, pas
déduits du code. C'est ce contrôle qui a trouvé le défaut du §7.

## 6. La carte FinanceAI trop vide (23/09) — `[H-29]`, PR #66

### Le diagnostic, qui n'était pas celui qu'on attendait

**Ce n'était ni FinanceAI ni le contrat.** FinanceAI publie déjà les **6 métriques** du plafond,
plus des alertes, un conseil et des blocs de détail. La carte du héros est **réservée sur 2×2
cases** avant que les données n'arrivent — pour que la page ne saute pas pendant que les apps
répondent — et son contenu n'en remplissait qu'une. Le bouton étant collé en bas, tout le surplus
se ramassait en **un seul trou de ~420 px**, mesuré sur ta capture.

### Ce qui occupe la place maintenant — rien d'inventé, tout était déjà publié

- Les alertes suivantes sont **listées** au lieu d'être réduites à « + 1 autre alerte ».
- Un **aperçu des blocs de détail**, borné à 2 sections × 4 lignes.
- Le **conseil revient**, en une ligne avec son icône — le « pourquoi » reste en page de détail.
- Une **courbe sous chaque chiffre secondaire**, pas seulement sous le gros.
- Un **jeu d'icônes SVG** : triangle pour une alerte, cercle pour un avertissement (deux
  *formes*, pas seulement deux couleurs), ampoule pour le conseil, flèches pour les tendances,
  horloge pour la fraîcheur.

### Deux arbitrages du 15/09 revus, sur ta demande

1. Le conseil avait quitté la carte (« faut aussi moins de texte »). Il revient **compact**.
2. Les détails étaient « rendus ici et nulle part ailleurs ». La raison — *48 lignes casseraient
   la grille* — reste vraie pour 48 lignes : d'où la borne à 8, et seulement sur la carte qui a
   deux rangées réservées. Le commentaire devenu faux a été corrigé dans la même PR.

### Garde-fous tenus

- **Le hub ne connaît toujours aucune app** : ce qui décide du contenu est la *taille* de la
  carte (une décision de mise en page du hub), et les icônes sortent de la *gravité* publiée —
  jamais de l'identité de l'app.
- **Icônes ≠ emojis** : ta règle « pas d'emoji dans l'interface » tient. Un emoji est un
  caractère dessiné par la police du téléphone ; ces icônes sont des dessins qui prennent la
  couleur du texte.
- **Une carte d'une seule colonne ne grossit pas** : chaque test « carte large » a son jumeau
  « carte normale ».

### Vérifié

Gate complet vert (440 tests) · **9 perturbations**, un rouge chacune · SonarCloud **0 % de
duplication** — c'était le piège à éviter en rendant les mêmes lignes à deux endroits ·
fusionnée par l'auto-merge du dépôt · production `READY` sur `hubperso.com`.

## 10. Pièges rencontrés — ce que la prochaine session doit savoir

Chacun a coûté du temps ou produit une fausse conclusion au moins une fois cette semaine.

1. **Une PR en conflit ne reçoit AUCUN run de CI.** Le symptôme est un silence, pas un rouge :
   zéro job, pendant que SonarCloud continue de passer. Devant une CI absente, soupçonner le
   conflit avant la lenteur. Vécu trois fois.
2. **`mergeable_state: "unknown"` n'est pas `"clean"`.** GitHub le calcule à la demande : il
   faut redemander la PR une seconde fois. Deux PR en conflit ont failli passer pour saines.
3. **« Garder les deux côtés » d'un conflit peut ré-introduire ce que l'autre côté avait
   retiré.** Chez FinanceAI, la PR #993 avait déménagé les items cochés vers l'archive ; une
   résolution mécanique les aurait remis dans le backlog, et une garde les plafonne à 6.
4. **Git ne voit pas une relation entre deux lignes.** Un rebasage sans conflit peut rendre
   fausse une valeur qu'on avait mesurée sur l'ancien code (§7, MemoryAI). Après un rebasage,
   re-mesurer ce que la branche avait **dérivé** d'un autre fichier.
5. **L'audit de dépendances peut échouer sans vulnérabilité** : `npm audit --omit=dev` a reçu
   un **400** d'un point d'entrée que npm annonce en cours de retrait. Vert à la relance. Même
   symptôme ailleurs → relancer avant de chercher dans le diff.
6. **Un déploiement Vercel peut rester en file plus d'une heure** sur le compte gratuit, sans
   aucune ligne de journal, puis partir seul. `QUEUED` n'est pas `ERROR`.
7. **Une mesure lancée avant `READY` lit l'ANCIEN build.** Toujours vérifier l'état du
   déploiement avant de lire ce qu'il sert.
8. **Le proxy de cette session bloque la plupart des domaines `*.hubperso.com`.** La lecture
   passe par l'outil Vercel, qui atteint l'URL du déploiement.
9. **Une branche fusionnée en squash ne paraît pas fusionnée** à l'ancêtre git : il faut
   chercher sa PR, pas comparer les commits.
